=====================================================================
БИЛЕТ № 3. Windows Server 2025: DHCP, DNS и NAT без Active Directory
(по ЛР ОРСОС №6 «Настройка DHCP, DNS, NAT на Windows Server 2025»)
=====================================================================

ЗАДАНИЕ ИЗ БИЛЕТА
- Сервер с двумя адаптерами: внешний - получает адрес по DHCP от
  "провайдера"; внутренний - статический 192.168.10.1/24.
- Во внутренней сети не меньше ТРЁХ клиентов, адреса - автоматически.
- AD нет. Сервер = DHCP-сервер + DNS-сервер + шлюз NAT.
- ДО начала настройки ЗАПИСАТЬ внешний IP - он нужен для проверки NAT.

СХЕМА (как в лабе)
  [интернет / сеть провайдера 192.168.122.0/24, шлюз 192.168.122.1]
                     |
            Ethernet (внешний, DHCP: напр. 192.168.122.130)
            СЕРВЕР WIN-7A69D86MP4P   (DHCP + DNS + NAT)
            Ethernet 2 (внутренний, 192.168.10.1/24)
                     |
       [внутренняя сеть 192.168.10.0/24: клиент1, клиент2, клиент3]
       клиенты получают адреса 192.168.10.50 - 192.168.10.200

ЗАЧЕМ КАЖДАЯ СЛУЖБА
  DHCP - раздаёт клиентам адрес, маску, ШЛЮЗ (192.168.10.1) и DNS (192.168.10.1).
  DNS  - отвечает на имена зоны college.local (внешние имена вроде ya.ru
         сервер находит сам - через корневые серверы).
  NAT  - подменяет внутренний адрес клиента на ВНЕШНИЙ адрес сервера,
         чтобы клиенты из 192.168.10.0/24 выходили во внешнюю сеть.

Команды - в PowerShell "от имени администратора".
Имя сервера у тебя будет своё - смотри командой hostname.


---------------------------------------------------------------------
ШАГ 1. Адаптеры                                         [ГДЕ: сервер]
---------------------------------------------------------------------
ipconfig /all
#  ЗАЧЕМ: найти, какой адаптер внешний, какой внутренний.
#  Ethernet   - внешний: "DHCP включен: Да", адрес напр. 192.168.122.130,
#               шлюз 192.168.122.1.   >>> ЗАПИСАТЬ ЭТОТ АДРЕС! <<<
#  Ethernet 2 - внутренний: пока адрес 169.254.x.x (APIPA - DHCP-сервера
#               во внутренней сети ещё нет).

netsh interface ipv4 set address name="Ethernet 2" static 192.168.10.1 255.255.255.0
#  name="Ethernet 2" - какой адаптер; static - статический адрес; адрес и маска.
#  ШЛЮЗ НА ВНУТРЕННЕМ НЕ ЗАДАЁМ: наружу сервер ходит через Ethernet.
#  (GUI-вариант: ncpa.cpl -> Ethernet 2 -> Свойства -> IPv4)

ipconfig /all
#  у Ethernet 2: "DHCP включен: Нет", 192.168.10.1, 255.255.255.0
netsh interface ipv4 show interfaces
#  точные имена интерфейсов (пригодятся для NAT)
hostname
#  имя сервера, напр. WIN-7A69D86MP4P (пригодится для записи A в DNS)


---------------------------------------------------------------------
ШАГ 2. DHCP                                             [ГДЕ: сервер]
---------------------------------------------------------------------
Install-WindowsFeature DHCP -IncludeManagementTools
#  ставит роль DHCP; -IncludeManagementTools - ещё и консоль DHCP + модуль PowerShell

Диспетчер серверов -> Средства -> DHCP -> раскрыть сервер ->
ПКМ "IPv4" -> "Создать область":
  Имя:            InternalScope           (чтобы различать области)
  Диапазон:       192.168.10.50 - 192.168.10.200, длина 24 / маска 255.255.255.0
  Исключения:     нет  (192.168.10.1 сервера и так не входит в диапазон)
  Срок аренды:    0 дн 8 ч 0 мин  (через половину срока клиент продлевает)
  Настроить параметры DHCP сейчас: Да
  Маршрутизатор (шлюз): 192.168.10.1 -> Добавить
      ЗАЧЕМ: клиенты шлют весь трафик наружу на сервер, а там работает NAT.
      Внешний адрес сюда НЕ пишем!
  Имя домена и DNS: родительский домен пусто, IP 192.168.10.1 -> Добавить
      ЗАЧЕМ: клиенты будут спрашивать имена у нашего сервера.
  WINS: пусто (NetBIOS не используем)
  Активировать область: Да  (неактивная область адреса НЕ выдаёт)
  -> Готово
Авторизация в AD НЕ нужна - сервер не в домене. (Жёлтый флажок в диспетчере
серверов про "завершить настройку DHCP" можно закрыть.)

# То же самое в PowerShell (если нужно быстро):
#  Add-DhcpServerv4Scope -Name "InternalScope" -StartRange 192.168.10.50 -EndRange 192.168.10.200 -SubnetMask 255.255.255.0 -LeaseDuration 08:00:00 -State Active
#  Set-DhcpServerv4OptionValue -ScopeId 192.168.10.0 -Router 192.168.10.1 -DnsServer 192.168.10.1 -Force
#  (-Force - не проверять DNS-сервер, если роль DNS ещё не стоит)


---------------------------------------------------------------------
ШАГ 3. DNS                                              [ГДЕ: сервер]
---------------------------------------------------------------------
Install-WindowsFeature -Name DNS -IncludeManagementTools
#  Success = True, Restart Needed = No

Средства -> DNS -> сервер -> "Зоны прямого просмотра" ->
Действие -> "Создать новую зону":
  Тип:  Основная зона  (флажок "Хранить в AD" серый - сервер не контроллер домена,
        поэтому зона будет в ФАЙЛЕ)
  Имя:  college.local
  Файл: college.local.dns (создать новый) - лежит в %SystemRoot%\System32\dns
  Динамическое обновление: Запретить
  -> Готово

college.local -> ПКМ -> "Создать узел (A или AAAA)":
  WIN-7A69D86MP4P = 192.168.10.1       (запись самого сервера)
  client1         = 192.168.10.100
  Флажок "Создать PTR" НЕ ставим - обратной зоны нет, будет предупреждение.
college.local -> ПКМ -> "Создать псевдоним (CNAME)":
  www -> WIN-7A69D86MP4P.college.local
  ЗАЧЕМ: www.college.local указывает на сервер; поменяем сервер - правим одну запись A.

SOA и NS создаются сами.

# PowerShell-вариант:
#  Add-DnsServerPrimaryZone -Name "college.local" -ZoneFile "college.local.dns" -DynamicUpdate None
#  Add-DnsServerResourceRecordA -ZoneName "college.local" -Name "WIN-7A69D86MP4P" -IPv4Address 192.168.10.1
#  Add-DnsServerResourceRecordA -ZoneName "college.local" -Name "client1" -IPv4Address 192.168.10.100
#  Add-DnsServerResourceRecordCName -ZoneName "college.local" -Name "www" -HostNameAlias "WIN-7A69D86MP4P.college.local"
#  Get-DnsServerResourceRecord -ZoneName "college.local"     # проверить записи

ШАГ 4. NAT                                              [ГДЕ: сервер]
---------------------------------------------------------------------
Install-WindowsFeature -Name RemoteAccess, Routing -IncludeManagementTools
#  роли "Удалённый доступ" + "Маршрутизация" и консоль RRAS

Средства -> "Маршрутизация и удаленный доступ" -> ПКМ по серверу ->
"Настроить и включить маршрутизацию и удаленный доступ":
  "Особая конфигурация"
     ЗАЧЕМ: тут можно сразу включить и NAT, и маршрутизацию локальной сети.
  [x] Преобразование сетевых адресов (NAT)
  [x] Маршрутизация локальной сети
  -> Готово -> "Запустить службу"
  (Предупреждение про ICS: NAT не стартует, если включён общий доступ к Интернету.)

IPv4 -> ПКМ "Преобразование сетевых адресов (NAT)" -> "Новый интерфейс":
  Ethernet   -> "Общий интерфейс подключен к Интернету"
                + [x] "Включить NAT на данном интерфейсе"
                ЗАЧЕМ: на нём адрес отправителя меняется на внешний IP сервера.
  Ethernet 2 -> "Частный интерфейс подключен к частной сети"
                ЗАЧЕМ: отсюда в NAT приходит трафик клиентов.
Пока клиенты ничего не отправляли, счётчики NAT = 0.


---------------------------------------------------------------------
ШАГ 5. ПРОВЕРКА НА КЛИЕНТАХ (их нужно 3)
---------------------------------------------------------------------
Клиенты подключены ТОЛЬКО к внутренней сети и получают адрес по DHCP.

--- Linux-клиент ---
nmcli device disconnect eth1; nmcli device connect eth1
#  ЗАЧЕМ: заново запросить адрес у DHCP (eth1 - интерфейс внутренней сети, смотри ip a)
ip a                      # 192.168.10.50/24 ... dynamic  - адрес из нашей области
ip route                  # default via 192.168.10.1 proto dhcp  - шлюз от DHCP
cat /etc/resolv.conf      # nameserver 192.168.10.1  - DNS от DHCP

nslookup WIN-7A69D86MP4P.college.local     # 192.168.10.1 - запись A
nslookup www.college.local                  # canonical name = WIN-7A69D86MP4P... - CNAME работает
nslookup ya.ru                              # внешние имена тоже резолвятся

ping -c 4 192.168.122.1
#  шлюз ВНЕШНЕЙ сети отвечает. TTL=63 (было 64) = пакет прошёл через
#  один маршрутизатор - наш сервер.
ping -c 4 ya.ru           # интернет через NAT работает

--- Windows-клиент ---
ipconfig /release
ipconfig /renew           # получить адрес заново
ipconfig /all             # адрес 192.168.10.x, шлюз и DNS 192.168.10.1, DHCP-сервер 192.168.10.1
nslookup www.college.local
ping ya.ru
tracert -d 8.8.8.8        # первый хоп - 192.168.10.1 (наш сервер)

--- На сервере ---
DHCP -> IPv4 -> Область [192.168.10.0] InternalScope -> "Арендованные адреса"
#  видны ВСЕ три клиента; "Уникальный код" = MAC клиента (сверить с ip a / ipconfig /all)
#  PowerShell:  Get-DhcpServerv4Lease -ScopeId 192.168.10.0

RRAS -> IPv4 -> NAT -> счётчики "сопоставлений" и "преобразованных пакетов"
растут на Ethernet. ПКМ по Ethernet -> "Показать сопоставления":
#  видно: частный адрес клиента 192.168.10.x  ->  ОБЩИЙ адрес = тот самый
#  внешний IP, который ты записал в шаге 1 (напр. 192.168.122.130).
#  ЭТО И ЕСТЬ ДОКАЗАТЕЛЬСТВО РАБОТЫ NAT - поэтому адрес надо было записать.
#  (Ещё вариант: на хосте во внешней сети tcpdump -n -i virbr0 icmp -
#   пинги клиентов приходят с адреса 192.168.122.130, а не 192.168.10.x.)


---------------------------------------------------------------------
ЧАСТЫЕ ОШИБКИ
---------------------------------------------------------------------
- Не записал внешний IP -> нечем доказать NAT.
- Перепутал общий/частный интерфейс в NAT -> клиенты не выходят наружу.
- Забыл галочку "Включить NAT на данном интерфейсе" на Ethernet.
- Область DHCP не активирована -> клиенты получают 169.254.x.x.
- В DHCP шлюзом указал внешний адрес -> неверно, шлюз = 192.168.10.1.
- Поставил флажок PTR без обратной зоны -> предупреждение (не страшно, но лишнее).
- Клиент подключён не к той сети (не к внутренней) -> адрес не из нашей области.
